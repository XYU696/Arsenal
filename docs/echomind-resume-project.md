# EchoMind 简历项目描述

## 项目名称

EchoMind - 企业级智能客服 AI 系统

## 项目定位

基于 `FastAPI + LLM + Redis + ChromaDB + Next.js` 构建的智能客服系统原型，面向企业客服场景，集成了意图识别、知识库检索、会话记忆、监控反馈、自动评测和业务规则热加载能力。

## 一句话版本

负责搭建并扩展一个企业客服 AI 系统，完成前后端联调与工程化改造，打通了“意图识别 - 路由编排 - RAG 检索 - 会话记忆 - 在线监控 - 自动评测”的完整链路。

## 简历描述版本一：偏后端/LLM 工程

- 设计并实现基于 `FastAPI` 的智能客服后端主链路，串联意图识别、知识库检索、对话上下文构建、Agent 路由和回复生成流程。
- 搭建基于 `Redis + ChromaDB` 的分层记忆系统，支持短期会话记忆、长期历史语义召回和用户画像管理，提升多轮对话上下文质量。
- 接入基于 ChromaDB 的 RAG 检索能力，并结合查询改写、并行召回、结果重排、缓存、熔断和 fallback 机制，增强知识库检索质量与系统稳定性。
- 实现三路融合意图识别方案，综合使用 LLM 语义理解、Embedding 相似度和关键词规则，输出意图分类、紧急度和实体抽取结果。
- 搭建在线监控与闭环反馈模块，周期采集 Agent 和工具运行指标，基于成功率和延迟动态调整路由惩罚项，并通过 Prometheus / Webhook 对外暴露监控能力。
- 实现端到端自动评测框架，支持意图识别准确率、Macro-F1、LLM-as-Judge 对话质量评分和回归检测，形成可持续评估机制。

## 简历描述版本二：偏全栈/系统整合

- 参与搭建企业级智能客服系统 EchoMind，负责梳理代码架构并补充独立 `Next.js` 前端控制台，实现前后端分离部署。
- 前端实现对话工作台、知识库管理、监控中心、Skills 管理和评测实验室页面，完成与后端 `/chat`、`/monitor`、`/skills`、`/eval/run` 等接口联调。
- 修复模型兼容层与前端长请求代理问题，提升 DeepSeek Anthropic 兼容接口下的响应稳定性，并解决评测接口在前端代理链路中的连接中断问题。
- 结合现有后端能力，完善项目启动配置、Docker 构建与前端部署链路，形成可演示、可联调、可迭代的全栈原型系统。

## 面试表达版本

这个项目本质上是一个面向企业客服场景的 LLM 工程化原型。我主要关注的是它如何把多个模块串成完整闭环：用户请求进入后，系统会先读取会话记忆和用户画像，再做意图识别和知识库检索，随后通过多角色客服编排器生成回复，并将运行数据交给监控模块与评测模块持续反馈。虽然它的多 Agent 更偏向基于意图路由的多角色编排，而不是自治式智能体协作，但在工程层面已经具备较完整的检索、记忆、监控、评测和规则热加载能力。

## 建议写法

### 如果投后端 / AI 应用工程岗

优先强调：

- 主链路设计
- RAG 检索
- 记忆系统
- 监控与评测
- LLM 工程化

### 如果投全栈 / AI 产品工程岗

优先强调：

- 前后端分离改造
- 控制台设计与联调
- Docker 部署
- API 集成
- 可观测页面建设

## 不建议夸大的表述

尽量避免直接写：

- “实现了完整自治多 Agent 系统”
- “实现了 Agent 自主工具调用”
- “实现了 Agent 长期记忆学习”

更准确的说法是：

- “实现了基于意图路由的多角色客服编排”
- “搭建了可扩展的工具调用与知识库检索框架”
- “实现了会话记忆、长期历史召回与用户画像管理”
- “构建了监控、评测和规则热加载等工程化能力”
